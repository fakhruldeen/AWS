# 03 — المجال الثالث: تطبيقات النماذج التأسيسية (`Domain 3 — 28%` — الأعلى وزناً!)

> **الوزن النسبي في الاختبار:** `28%` (أكبر مجال في `AIF-C01`)  
> **المهام الرسمية:** `Task 3.1` (التصميم و `RAG` وقواعد المتجهات) • `Task 3.2` (هندسة وإدارة الأوامر `Prompt Management`) • `Task 3.3` (التدريب و `Fine-Tuning` و `Distillation`) • `Task 3.4` (مقاييس تقييم الأداء)

---

## 1. معاملات الاستدلال (`Inference Parameters`) وتحسين التكلفة
- **Temperature (`0.0` إلى `1.0+`):** يتحكم في العشوائية والإبداع.
  - **قيمة منخفضة (`0.0–0.2`):** إجابات حتمية ودقيقة ومباشرة (الأفضل للقانون، البرمجة، `SQL`، واستخراج الحقائق).
  - **قيمة مرتفعة (`0.7–1.0`):** إجابات إبداعية ومتنوعة (التسويق وكتابة القصص).
- **Top-P (`Nucleus Sampling`):** يختار من أصغر مجموعة رموز يتجاوز مجموع احتمالاتها القيمة `P`.
- **Top-K:** يحصر الاختيار في أعلى `K` رمز من حيث الاحتمالية فقط.
- **Prompt Caching (التخزين المؤقت للأوامر — `v1.2`):** يحفظ البادئة الثابتة المتكررة (مثل تعليمات النظام أو مستند سياسات ضخم) عبر الطلبات ← **يقلل تكلفة رموز الإدخال وزمن الاستجابة دون تغيير النموذج**.

---

## 2. التوليد المعزز بالاسترجاع (`RAG`) وقواعد بيانات المتجهات في AWS
- **آلية `RAG` (`Amazon Bedrock Knowledge Bases`):** بدلاً من إعادة تدريب النموذج عند تغيّر بيانات الشركة، يتم استرجاع المقاطع المحدثة من قاعدة متجهات وإضافتها إلى سياق السؤال ← **يقلل الهلوسة، يوفّر استشهادات بالمصادر (`Citations`)، ويبقي المعلومات محدثة باستمرار**.
- **قواعد المتجهات المعتمدة في الاختبار (`Task 3.1`):**
  1. [`Amazon OpenSearch Service`](../AWS_AI_SERVICES_GLOSSARY.md#amazon-opensearch-service) (`OpenSearch Serverless` — الخيار الافتراضي في `Bedrock Knowledge Bases`).
  2. [`Amazon Aurora`](../AWS_AI_SERVICES_GLOSSARY.md#amazon-aurora) (مع امتداد `pgvector`).
  3. [`Amazon RDS for PostgreSQL`](../AWS_AI_SERVICES_GLOSSARY.md#amazon-rds) (مع `pgvector`).
  4. [`Amazon Neptune`](../AWS_AI_SERVICES_GLOSSARY.md#amazon-neptune) (لتطبيقات **`GraphRAG`** والعلاقات المعقدة بين الكيانات).

---

## 3. سُلّم تخصيص النماذج وتكاليفها (`FM Customization Tradeoffs`)

| الأسلوب | التكلفة والجهد | متى تختاره في الاختبار؟ |
| :--- | :---: | :--- |
| **Prompt Engineering / In-Context Learning** | الأقل | خط البداية الدائم؛ مهام عامة دون تعديل أوزان النموذج |
| **RAG (`Bedrock Knowledge Bases`)** | منخفضة–متوسطة | بيانات مؤسسية متغيرة باستمرار + الحاجة لتوثيق المصادر |
| **Model Distillation (تقطير النموذج — `v1.2`)** | متوسطة | نقل جودة نموذج **معلم (`Teacher`)** ضخم إلى نموذج **طالب (`Student`)** صغير وسريع ورخيص لمهمة محددة عالية الكثافة |
| **Instruction Fine-Tuning / PEFT (`LoRA`)** | متوسطة–مرتفعة | تعليم النموذج أسلوباً أو نبرة أو تنسيقاً محدداً باستخدام أمثلة مُصنّفة (`Labeled Prompt-Completion Pairs`) |
| **Continued Pre-Training** | مرتفعة | إكساب النموذج مفردات قطاع متخصص من نصوص **غير مُصنّفة (`Unlabeled`)** ضخمة (طبي، قانوني، مالي) |
| **Pre-Training from Scratch** | الأعلى إطلاقاً | بناء نموذج تأسيسي جديد كلياً (نادر جداً ومكلف للغاية) |

- **`RLHF` (التعلم المعزز من التغذية الراجعة البشرية):** يُستخدم لمواءمة إجابات النموذج مع القيم البشرية (المساعدة، الصدق، الأمان).

---

## 4. هندسة الأوامر (`Prompt Engineering`) ومخاطرها وإدارتها
- **التقنيات الأساسية:** `Zero-Shot` (بدون أمثلة) • `Single-Shot` (مثال واحد) • `Few-Shot` (2–5 أمثلة لضبط التنسيق) • **`Chain-of-Thought (CoT)`** (اطلب التفكير خطوة بخطوة للمنطق والحساب) • `Negative Prompts` (تحديد ما يجب استبعاده) • `Prompt Templates`.
- **إدارة الإصدارات (`v1.2`):** [`Amazon Bedrock Prompt Management`](../AWS_AI_SERVICES_GLOSSARY.md#amazon-bedrock) لإنشاء وإصدار ومقارنة ونشر قوالب الأوامر عبر بيئات التطوير والإنتاج.
- **مخاطر الأوامر:** `Prompt Injection / Hijacking` (تجاوز تعليمات النظام عبر إدخال خبيث) • `Jailbreaking` (التحايل على فلاتر الأمان) • `Exposure` (تسريب تعليمات النظام) • `Poisoning` (تسميم بيانات التدريب أو `RAG`).

---

## 5. مقاييس تقييم أداء النماذج التأسيسية (`FM Evaluation — Task 3.4`)

| المقياس / الأسلوب | الاستخدام الأمثل في الاختبار |
| :--- | :--- |
| **ROUGE** (`Recall-Oriented`) | تقييم **التلخيص النصي (`Text Summarization`)** |
| **BLEU** (`Precision-Oriented`) | تقييم **الترجمة الآلية (`Machine Translation`)** |
| **BERTScore** | قياس **التشابه الدلالي (`Semantic Similarity`)** باستخدام التضمينات حتى عند اختلاف الكلمات الحرفية |
| **Perplexity** | قياس قدرة النموذج على توقع الكلمة التالية (**القيمة الأقل أفضل**) |
| **LLM-as-a-Judge (`v1.2`)** | استخدام نموذج تأسيسي قوي كمُقيّم آلي لتقييم الإجابات المفتوحة (الدقة، الأمانة، الفائدة) على نطاق واسع عبر `Bedrock Model Evaluation` |
| **Human-in-the-Loop (`HITL`)** | المعيار الذهبي لتقييم النبرة والإنصاف والحالات الحساسة |
| **مقاييس الأعمال (`Business Alignment`)** | معدل إتمام المهام (`Task Completion Rate`)، رضا المستخدم، وتكلفة التفاعل الواحد (`Cost per Interaction`) |
